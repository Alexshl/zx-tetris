# Тетрис для ZX Spectrum 128K на z88dk

## Context

Пет-проект ради ностальгии: классический Тетрис для ZX Spectrum 128K. Пользователь — новичок в low-level разработке (опыт в высокоуровневых языках), но хочет писать на C, а не на ассемблере. Цель — собрать рабочую игру в `.tap`-образе, запустить и поиграть в эмуляторе Fuse на macOS.

Решения, принятые в ходе discovery:

| Что | Выбор | Почему |
|-----|------|--------|
| Платформа | ZX Spectrum 128K (+2/+3) | AY-чип, 128 КБ, современный стандарт сцены |
| Тулчейн | z88dk (C → Z80 asm → бинарник) | Настоящий C-компилятор для Z80, готовые либы для Спектрума, активно поддерживается |
| Графика | Bitmap mode 256×192 | Стакан рисуем как сетку 16×8 пиксельных блоков, HUD — текстом поверх |
| Геймплей MVP | 7 тетромино, поворот, soft/hard drop, нарастающий темп | Классический Тетрис без современных усложнений (no SRS / hold / ghost) |
| HUD | Счёт, уровень, линии | Без них Тетрис теряет смысл |
| Ввод | Клавиатура QAOP + Space (hard drop) + Enter (rotate) | Классическая Spectrum-раскладка |
| Звук | Простые SFX через бипер | Lock-блок / clear-линия / game-over. Без AY-музыки в MVP |
| Эмулятор | Fuse for macOS | Стандарт для Mac/Linux ZX-сцены, грузит `.tap` |

## Toolchain setup (macOS)

### 1. z88dk

z88dk — это набор `zcc` (фронтенд) + SDCC (backend) + библиотеки для Z80-машин. Есть target `+zx` (48K) и `+zx -subtype=zx-128`/`-pragma-include` для 128K. На macOS установить лучше через nightly из репозитория (Homebrew formula устаревает):

```bash
git clone --recursive https://github.com/z88dk/z88dk.git ~/tools/z88dk
cd ~/tools/z88dk
./build.sh   # собирает sccz80, zsdcc, ассемблер, либы — займёт 10-20 минут
```

После сборки добавить в `~/.zshrc`:

```bash
export Z88DK=$HOME/tools/z88dk
export PATH=$Z88DK/bin:$PATH
export ZCCCFG=$Z88DK/lib/config
```

Проверка: `zcc +zx -clib=new --help` должно показать справку.

### 2. Fuse эмулятор

```bash
brew install --cask fredm-fuse
```

Запуск с автозагрузкой `.tap`: `open -a "Fuse" build/tetris.tap` или из меню Fuse `File → Open → tetris.tap`. В настройках выбрать machine = **Spectrum 128**.

## Архитектура

### Игровое поле

- Доска **10 × 20 клеток**, каждая клетка = `uint8_t` (0 = пусто, 1..7 = id фигуры → цвет).
- Хранится как `uint8_t board[20][10]` (200 байт — копейки на 128К).
- Активная фигура: id (0..6), текущий поворот (0..3), позиция `x,y` верхнего-левого угла 4×4 бокса.

### Тетромино

Каждое тетромино — 4×4 битовая маска × 4 поворота × 7 фигур = 7 × 4 × 2 байта = 56 байт таблица. Хранить как `const uint16_t pieces[7][4]` во flash-разделе кода (z88dk кладёт `const` в ROM-зону при правильном пragma).

Цвета фигур (атрибуты Spectrum: INK 0-7):
- I = голубой (5), O = жёлтый (6), T = пурпурный (3), S = зелёный (4), Z = красный (2), L = оранжевый (нет — заменить на жёлтый+яркий), J = синий (1).

### Рендеринг

ZX Spectrum экран = 256×192 пикселя (битмап 6 КБ в `0x4000`) + атрибутный файл 32×24 (768 байт в `0x5800`). Каждый знакоместо (8×8 пикс) имеет ОДИН цвет INK и ОДИН PAPER — это «attribute clash».

Решение: **1 клетка Тетриса = 1 знакоместо 8×8 пикс**. Тогда:
- Стакан 10×20 знакомест = 80×160 пикселей.
- Размещаем стакан со смещением (88, 16) → центрирован.
- HUD справа: «SCORE / LEVEL / LINES» текстом через стандартные `printf`/`puts` z88dk (target zx уже имеет вывод в ROM-шрифт).
- Блок рисуется записью одного байта `0xFF` в 8 строк битмапа + атрибут с цветом фигуры в атрибутном файле.
- z88dk даёт `zx_pxy2saddr()` / `zx_pxy2aaddr()` для расчёта адресов экрана/атрибутов из пиксельных координат.

### Главный цикл

Spectrum даёт прерывание каждые 1/50 секунды. В z88dk `intrinsic_halt()` ждёт следующего vsync — это даёт стабильный 50 Hz tick.

```c
while (!game_over) {
    intrinsic_halt();             // ждём vsync (50 Hz)
    frame++;
    input_poll();                 // QAOP, Space, Enter
    apply_input();                // перемещение / поворот / hard drop
    if (frame % drop_period == 0) // drop_period зависит от уровня
        gravity_step();
    render_frame();
    sfx_tick();
}
```

`drop_period` в фреймах: уровень 0 → 48 фр (≈1 с), потом по таблице как в NES Tetris.

### Ввод

z88dk даёт `in_key_pressed(IN_KEY_SCANCODE_*)` — макросы scancode'ов. Для QAOP+Space+Enter использовать:
- `IN_KEY_SCANCODE_o` / `_p` — влево/вправо
- `IN_KEY_SCANCODE_q` — поворот (или Enter)
- `IN_KEY_SCANCODE_a` — soft drop
- `IN_KEY_SCANCODE_SPACE` — hard drop

Дебаунс: для движения — autorepeat каждые ~6 фреймов после задержки 12 фреймов. Для поворота и hard drop — только по фронту нажатия.

### Звук

Бипер на Спектруме = тоггл бита 4 в порту 0xFE. z88dk даёт `bit_beep()` / `bit_beepfx_di()` или можно вызвать встроенный ROM beeper по адресу `0x03B5`. Для MVP хватит вызовов `bit_beepfx_di(N, FREQ)` с короткими таблицами:
- `sfx_lock()` — низкий щелчок
- `sfx_line_clear()` — восходящий «бип-бип»
- `sfx_game_over()` — нисходящий звук

## Makefile (концепт)

```make
PROJECT = tetris
SRCS = src/main.c src/game.c src/pieces.c src/render.c src/input.c src/sound.c
CFLAGS = +zx -vn -SO3 -clib=new -pragma-include:zpragma.inc
LDFLAGS = -create-app -subtype=tap

all: build/$(PROJECT).tap

build/$(PROJECT).tap: $(SRCS)
	@mkdir -p build
	zcc $(CFLAGS) $(SRCS) -o build/$(PROJECT) $(LDFLAGS)

run: build/$(PROJECT).tap
	open -a "Fuse" build/$(PROJECT).tap

clean:
	rm -rf build/
```

Файл `zpragma.inc` (в корне проекта) — настройки памяти, для 128K:

```
#pragma output STACKPTR=61440   // стек ниже экрана
#pragma output CRT_ORG_CODE=24576  // загрузка с $6000 над экраном
```

## Порядок реализации

Это «дорожная карта» по инкрементам. Каждый шаг даёт работающую программу — это важно для новичка: всегда есть что запустить и увидеть.

1. **Hello, Spectrum.** Setup z88dk + Fuse + Makefile. `main.c` печатает «TETRIS» и заканчивается бесконечным циклом. Цель: убедиться, что весь тулчейн собирает `.tap` и Fuse его грузит.
2. **Пустой стакан.** Рисуем рамку стакана и пустое поле 10×20 знакомест на правильных координатах. HUD-заглушки справа.
3. **Статичная фигура.** `pieces.c` с таблицей тетромино. Рисуем одну фигуру в фиксированной позиции. Проверяем все 7 × 4 поворота визуально (debug-режим: меняем поворот клавишами).
4. **Падение.** Реализуем `gravity_step()`: фигура падает раз в 48 фр. При коллизии с дном или другим блоком — «лочится» в массив `board[][]` и спавнится следующая.
5. **Управление.** `input.c`: движение влево/вправо, поворот, soft drop, hard drop. Дебаунс и autorepeat.
6. **Очистка линий.** При лочинге проверяем заполненные ряды → удаляем, сдвигаем доску вниз, увеличиваем счётчик линий.
7. **Счёт и уровень.** Очки за линии (NES-таблица: 40/100/300/1200 × (level+1)). Уровень растёт каждые 10 линий, `drop_period` сокращается по таблице.
8. **HUD.** Числовой вывод SCORE/LEVEL/LINES в правую колонку. Обновлять только при изменении (чтобы не моргало).
9. **Game Over.** Если новая фигура спавнится в занятой клетке — конец. Показать «GAME OVER», ждать клавишу для рестарта.
10. **Звук.** Три SFX через бипер (см. выше).

После 10 шагов — MVP готов.

## Verification

**Финальная сборка и тест:**

```bash
make run    # собирает tap и открывает в Fuse
```

В Fuse: `Machine → Spectrum 128`, дождаться загрузки, проверить:

- [ ] Стакан 10×20 отрисован, рамка на месте
- [ ] Все 7 фигур спавнятся, цвета правильные
- [ ] QAOP двигает/поворачивает, Space делает hard drop
- [ ] Линии очищаются, экран не моргает
- [ ] Счёт и уровень растут корректно
- [ ] На уровне 5+ фигуры падают заметно быстрее
- [ ] Звуковые эффекты слышны при лочинге, очистке, game over
- [ ] Game over срабатывает при переполнении и игру можно начать заново

**Пограничные кейсы для ручного теста:**

- Поворот I-фигуры у правой стенки (должен либо не сработать, либо сделать wall-kick — в нашем MVP без kicks просто блокируем).
- Очистка 4 линий сразу (Tetris) — счёт +1200×(L+1).
- Удержание hard drop — не должно зацикливать движение в новой фигуре.

## Критические файлы (создаются в реализации)

- `src/main.c` — точка входа, игровой цикл
- `src/game.c` / `game.h` — состояние, gravity, очистка линий, scoring
- `src/pieces.c` / `pieces.h` — таблица тетромино и операции с ними
- `src/render.c` / `render.h` — рисование стакана, фигуры, HUD
- `src/input.c` / `input.h` — опрос клавиатуры, дебаунс
- `src/sound.c` / `sound.h` — три SFX через бипер
- `Makefile` — сборка `.tap`
- `zpragma.inc` — настройки памяти z88dk

## Что НЕ делаем в MVP (вне скоупа)

- Next-piece превью (легко добавить позже)
- Hold piece, ghost piece, SRS wall-kicks
- AY-музыка (нужен внешний трекер и player — отдельная задача)
- Поддержка Kempston joystick
- Меню, рекорды, настройки
- Реальное железо: только эмулятор
